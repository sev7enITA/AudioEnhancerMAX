Privacy notice

Know where your audio goes

AudioEnhancerMAX is local-first, not absolutely offline. Core processing is local, while clearly identified optional features can contact local-network devices or external services.

01 / Scope

What this notice covers

This notice applies to the AudioEnhancerMAX macOS application, source distribution, Android edge worker and official project pages hosted at fabriziodegni.com/AudioEnhancerMAX. It explains processing performed by the software and separate processing that can occur through optional integrations or public project services.

Core position

The maintainer does not operate an AudioEnhancerMAX account service, advertising network or behavioral analytics service. The application does not automatically send recordings, outputs or diagnostic telemetry to the maintainer.

"Local-first" means that the core audio workflow is designed to run on the user's Mac. It does not mean that every optional feature is offline. The user controls whether to invoke network-dependent TTS, connect a trusted LAN worker, use local Ollama or visit an external project link.

02 / Data flows

Application processing by function

Function Data involved Default destination User control
Import and enhancement Selected audio or media, processing settings and outputs Local application storage The user selects the source file, modules and export action.
Transcription Audio and generated transcript Local Faster-Whisper processing when local models are available The user starts transcription and chooses whether to export the result.
Smart Mode Audio-derived analysis and prompt context User-controlled Ollama service, normally on the same Mac Optional. Core DSP remains available without Ollama.
Kokoro TTS User-entered text and generated speech Local processing when the engine and assets are installed The user selects the local engine and voice.
Personal Voice Studio (development head) Consensual voice samples, profile name, synthesis settings, training metadata and generated speech Local AudioEnhancerMAX storage and the separately installed local MakeMyVoice workspace/runtime The user must confirm consent, names the profile, starts synthesis, and can re-enrol or remove locally stored profile data.
Edge Neural TTS User-entered text, voice and synthesis settings Microsoft's network service Optional. Transfer occurs only when this engine is selected and synthesis is started.
Trusted LAN workers Audio chunks, filter settings and processing status Devices selected on the user's local network Optional. Use only on networks and devices the user controls or trusts.
Readiness and monitoring OS, architecture, memory, storage and processing status Local interface and local log files No automatic diagnostic submission to the maintainer.

AI-assisted transcripts, classifications and parameter suggestions can be inaccurate. They remain reviewable outputs and should not be treated as authoritative decisions in legal, medical, employment or other high-stakes contexts.

03 / Storage

Local storage and retention

The packaged GitHub application stores imported files, generated outputs, presets, timing history, readiness state and roadmap votes under ~/Library/Application Support/AudioEnhancerMAX. Development-head personal-voice profiles can also store a profile manifest, consent record, reference-audio copy or link, and synthesis defaults there. MakeMyVoice keeps its own datasets, checkpoints, comparisons and activated models in its separate local workspace. Launcher logs are stored under ~/Library/Logs/AudioEnhancerMAX. A sandboxed Mac App Store build stores equivalent supported data within its Apple-managed application container; MakeMyVoice integration is not currently claimed for that build.

Project data is retained locally until the user removes it. Some temporary processing files are deleted when their operation finishes, but imported files, outputs and saved settings can persist between sessions. AudioEnhancerMAX does not currently promise automatic deletion after a fixed period.

Deleting local data or uninstalling the app does not delete content separately submitted to GitHub, SourceForge, Microsoft or another selected third-party service. Those services apply their own retention rules.

04 / Public services

Website and support activity

The project website does not intentionally set first-party advertising or analytics cookies. Hosting infrastructure can process standard request information such as IP address, date, requested page, browser information and error status for delivery, security and operational logging.

The overview and roadmap pages can request fonts from Google and award metadata from SourceForge. Those providers receive normal web request data, which can include IP address and browser information. The privacy, support and accessibility pages use system fonts and do not load the SourceForge badge script.

When a user follows a link to GitHub or SourceForge, opens a support ticket, stars the project or signals roadmap interest, the destination platform processes account and activity data under its own policy. GitHub issues are public unless GitHub explicitly indicates otherwise.

05 / Third parties

Optional services and independent providers

  • Microsoft Edge Neural TTS: receives text and synthesis settings when that engine is selected.
  • MakeMyVoice: is a separate local project/runtime used by development-head personal-voice profiles. AudioEnhancerMAX does not upload those samples to a maintainer-operated service.
  • GitHub: hosts source code, releases, issues and roadmap feedback.
  • SourceForge: hosts releases, project activity and the Rising Star badge.
  • Google Fonts: can serve font files on the overview and roadmap pages.
  • Model and package providers: can receive network request data if the user chooses to obtain optional models or dependencies outside the packaged core.

AudioEnhancerMAX does not sell personal data and does not provide user recordings to advertisers. Optional providers are not controlled by the project maintainer, and their policies should be reviewed before enabling a network-dependent workflow.

06 / Control

User choices and data protection rights

Users can choose local engines, avoid optional network features, disconnect LAN workers, remove local project files and refrain from creating public support tickets. Source audio is not intentionally overwritten by the processing pipeline.

Depending on applicable law, a person can request access, correction, deletion, restriction, portability or objection regarding personal data controlled by the project maintainer, and can lodge a complaint with a competent supervisory authority.

Most application content is held only on the user's device and is therefore not accessible to the maintainer. Requests about information held by GitHub, Microsoft, SourceForge, Google or a hosting provider may need to be directed to that provider.

07 / Security

Safeguards, limitations and policy changes

The desktop service is designed to bind to the loopback interface 127.0.0.1. The project validates key storage identifiers and documents that the FastAPI service must not be exposed directly to the public internet without authentication, rate limits and an appropriate reverse-proxy policy.

No software or transmission method is risk-free. Users remain responsible for device access controls, backups, network trust, lawful consent to use a voice, and review of sensitive outputs. Trusted LAN processing should be enabled only on networks and devices the user controls. The Android worker path is currently treated as experimental while pairing, authentication, revocation, and workload limits are strengthened.

This notice will be updated when a release materially changes data flows. The effective date and notice version at the top identify the current text. Earlier behavior can also be reviewed through the open-source version history.

08 / Contact

Privacy contact

The data controller for project-maintained processing is Fabrizio Degni, maintainer of AudioEnhancerMAX.

To initiate a privacy request, create a minimal issue in the official repository identifying it as a privacy request. Do not include recordings, transcripts, identifiers or other private information in the public issue. The maintainer will identify an appropriate follow-up channel when needed.
